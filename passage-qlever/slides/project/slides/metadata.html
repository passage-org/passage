What is held in RAM

CompressedBlockMetadata — one per block

offsetsAndCompressedSize_one per column
numRows_rows in this block
firstTriple_col0, col1, col2, graph
lastTriple_col0, col1, col2, graph
graphInfo_graphs present, if few
containsDuplicates……WithDifferentGraphs_
blockIndex_its place in the file

CompressedRelationMetadata — one per relation

col0Id_the relation itself
numRows_its size
multiplicityCol1_1.0 means functional
multiplicityCol2_used by the planner
offsetInBlock_where it starts inside a shared block
= uint64 maxmeans: it owns its blocks

Every block’s numRows_ is exact and already in memory — the whole offset mechanism rests on that one field.

366 blocks for PSO, 234 for SPO, 249 for OPS: a few thousand records for a ten-million-triple index.

firstTriple_ and lastTriple_ are what the binary search uses to find the range of blocks a pattern touches, without reading any of them. numRows_ is what lets an offset be resolved before any I/O. Both were already there; nothing in this work added a field.
