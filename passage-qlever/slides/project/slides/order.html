Id order is value order

Permutations are sorted by a plain 64-bit integer compare on the Id. No string is ever compared. The order still comes out right, because the Ids are handed out that way.

Count the payload up, read the strings out

4000000000000000<http://ex.org/H1>
4000000000000001<http://ex.org/H2>
4000000000000002<http://ex.org/H3>
4000000000000003<http://ex.org/Human>

Byte-wise lexicographic: H3 < Human because ‘3’ < ‘u’, O3 < occupation because ‘O’ < ‘o’.

The 4-bit tag decides the group

1000000000000001"true"^^xsd:boolean
200000000000002A"42"^^xsd:int
20000000000003E8"1000"^^xsd:int
3800000000000000"-0.0"^^xsd:decimal
4000000000000000<http://ex.org/H1>

For Int the payload is the number — 42 is …002A. No vocabulary at all: this index contains no integers, and the Id still decodes.

Largest Int Id 2FFFFFFFFFFFFFFF < smallest IRI Id 4000000000000000 — so every number sorts before every IRI. That is the storage order, not the SPARQL order.
