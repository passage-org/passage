The explanation this slide used to give — a join is a sequence of point lookups, which suits a B-tree and not a block store — was not what the measurement said: the identical loop in C++ reaches Blazegraph’s figure, so what the published line attributed to the storage is mostly the JNI crossing, which only one of the two backends pays. Two further methodological notes, each of which cost a wrong conclusion first. "Warm" is two things — the JVM compiling the pipeline and the store's working set in memory — and conflating them hid a bad protocol; measured properly, the join comparison reversed. And a published Blazegraph scan-open figure turned out to have been measured on 187 triples out of eleven million, because its three-argument scan passes a null graph; it was withdrawn rather than corrected.
